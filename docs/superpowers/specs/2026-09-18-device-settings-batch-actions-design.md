# 设备设置批量操作设计

## 目标

把“批量修改”从设备管理一级菜单迁移到“设备设置”页面中的“批量操作”下拉菜单，同时保留现有源码和后端接口。下拉菜单包含“批量绑定”“批量解绑”“批量修改”三个入口，弹窗布局和字段按照用户提供的四张参考图实现。

## 范围

- 修改 `vue前端源码/vue-app/src/views/DeviceSettingsView.vue` 的设备设置页面。
- 修改 `vue前端源码/vue-app/src/App.vue`，从设备管理导航中移除独立的“批量修改”菜单项，但保留旧组件、旧渲染分支和权限代码，便于旧书签兼容。
- 新增纯函数到 `src/services/deviceBatch.js`，负责 IMEI/人员姓名解析和解绑集合计算。
- 新增对应 Node 测试；不修改 TCP 解析、FastAPI、PostgreSQL 或已有 HTTP 合同。

## 界面

设备设置页面增加：

1. 账号下拉筛选；
2. 设备型号下拉筛选；
3. IMEI 搜索框和搜索按钮；
4. “批量操作”按钮，菜单项严格为批量绑定、批量解绑、批量修改；
5. 导出按钮保留为页面占位，若当前页面没有导出专用合同则显示“暂未接入”，不能下载假数据；
6. 设备表格列：序号、姓名、设备 IMEI、归属账号、设备型号、状态、最后通信、电量、操作。

三个弹窗：

- 批量绑定：账号选择、设备 IMEI 多行输入、人员姓名多行输入、暂无人员名称提示、取消/确定。
- 批量解绑：设备 IMEI 多行输入、取消/确定。
- 批量修改：全选、已添加设备选择列表、上传频率和“分钟”单位、取消/确定。

## 真实接口映射

- 设备和表格：`GET /api/v1/devices`。
- 账号：管理员使用 `GET /api/v1/accounts`；非管理员不显示需要管理员权限的批量绑定/解绑操作。
- 绑定：必要时先用 `POST /api/v1/devices` 建立缺失设备，再用 `PATCH /api/v1/devices/{imei}` 更新人员姓名，最后用 `PUT /api/v1/accounts/{id}/bindings` 提交完整绑定集合。
- 解绑：读取当前账号的 `device_imeis`，移除输入的 IMEI，再调用同一个 `PUT /api/v1/accounts/{id}/bindings`。
- 批量修改：对选中的 IMEI 逐台调用现有 `POST /api/v1/commands`，命令类型为 `health_frequency`，然后读取现有命令状态。

所有请求继续使用现有 Bearer 登录令牌；浏览器不接触内部令牌。

## 协议边界

现有后端命令构造器对健康周期使用 2–255 分钟范围。界面可以保留参考图中的“1 分钟”选项作为不可选提示，但选择 1 分钟时必须显示协议限制并且不发送请求。默认可选值为 2 分钟，不能伪造设备已执行 1 分钟。

## 兼容和回滚

- 不删除 `BatchModifyView.vue`，不删除 `api.batchUpdateDevices`，不删除后端 `/api/v1/devices/batch`。
- 旧的 `#batch-modify` 仍可由管理员直接访问；新用户从设备设置中的批量操作进入。
- 现有健康、定位、报警、登录、退出和 TCP 数据链路不变。
