# 步数估算卡路里展示设计

## 目标

健康数据接口和 B2315P 当前 TCP 报文没有提供卡路里实测字段。前端根据真实步数计算一个可见、可追溯的卡路里估算值，使健康数据页面的卡路里趋势图、最新指标、表格和导出内容不再显示空白。

## 范围

- 修改 `vue前端源码/vue-app/src/views/HealthView.vue`，使健康数据表格、趋势图和导出内容显示估算卡路里。
- 修改 `vue前端源码/vue-app/src/views/HealthDetailView.vue`，使详情页最新指标、趋势图和导出内容显示估算卡路里。
- 在 `vue前端源码/vue-app/src/services/presentation.js` 增加纯函数，集中处理步数到卡路里的转换和健康指标取值。
- 在对应 Node 测试文件中增加边界测试。
- 不修改 FastAPI、PostgreSQL、TCP 解析程序和 HTTP 接口合同。

## 计算规则

```text
estimated_calories = steps × 0.04
```

- 默认换算系数为每步 `0.04 kcal`。
- 结果保留 1 位小数，例如 `180` 步显示 `7.2 kcal`。
- `0` 步是有效值，显示 `0.0 kcal`。
- `null`、空字符串、非数字、负数或无穷数不参与计算，显示 `--`，不能默认填 0。
- 页面文案只显示“卡路里”，不显示“估算”字样；实现和文档仍将该值定义为步数换算值，不宣称是手环实测值。

## 展示逻辑

所有页面使用同一个计算函数，避免列表、详情和图表出现不一致：

1. 健康数据表格的卡路里列显示当前记录步数对应的估算值。
2. 健康趋势图的卡路里每个点由对应记录的步数计算，不调用不存在的 `calories` 字段。
3. 健康详情页最新指标显示最后一条有效记录的估算卡路里；没有有效步数时显示 `--`。
4. 导出 Excel 的列标题使用“卡路里（kcal）”，导出的值与页面使用同一计算函数。
5. 图表为空的判断以是否存在有效步数为准；没有有效步数时仍显示“暂无测量数据”。

## 数据边界

- 原始 API 响应保持不变，不向服务器回写估算值。
- 估算值仅由当前已查询的每条健康记录计算；不跨日期额外推算，也不伪造缺失记录。
- 现有 `calories` 实测字段若将来由后端提供，第一阶段仍以步数估算为页面默认值；后续可单独制定“实测优先、估算回退”的兼容规则。

## 测试要求

至少覆盖：

- `180` 步得到 `7.2`；
- `0` 步得到 `0.0`；
- `null`、空值、非法字符串和负数返回缺失标记；
- 图表和导出调用同一计算结果；
- 现有健康数据、命令和路由测试不回归。

## 验收标准

- 页面卡路里图表在存在步数的真实健康记录时显示曲线，而不是“暂无测量数据”。
- 表格、详情和导出显示的估算数值一致。
- 页面和导出列显示“卡路里”，不出现“估算”字样。
- `npm test` 和 `npm run build` 均通过。
